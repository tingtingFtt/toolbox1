# 酒馆统一导入与大库处理

顶栏的「导入中心」支持多文件、文件夹和 ZIP。角色卡、预设、世界书、正则、脚本、QR、主题页面的本地文件选择也调用同一个导入流程。判断依据是文件内容，目录名不决定资源类型。

| 数据结构 | 放置位置 |
| --- | --- |
| PNG 的 ccv3 / chara 或角色卡 JSON | ST 角色卡 |
| prompts / prompt_order | ST 预设 |
| entries 数组或字典 | ST 世界书 |
| findRegex / replaceString | ST 正则：一份来源文件一个集合 |
| 真实脚本节点 content / code / script | ST 脚本：一份来源文件一个集合 |
| qrList 中的 message | ST QR 快捷回复：一个回复集合一个条目 |
| custom_css 或主题颜色设置、CSS 文件 | ST 主题 |
| 无法识别的结构 | 导入中心「待处理」，保留原文件 |

角色卡和预设内的正则、脚本按所属来源分组；集合详情再显示子条目。脚本文件夹中的变量配置不会当作脚本。QR 的隐藏、触发、发送、上下文关联等原字段保留，导入不会执行脚本、QR 或主题。

## 单文件调整与删除

每个文件记录类型、路径、来源、SHA-256、结果及产生的条目 ID。在导入中心选择「调整 / 重试」，可以自动重新识别、指定类型，或更换修正后的文件。仅成功识别后替换此记录产生的条目；失败保留旧条目并新增诊断记录。单个文件的重试不会重置其他来源。

删除来源记录会删除它产生的条目；角色卡的专属资源按现有级联规则清理。资源管理页仍支持单独删除集合。文件副本可能被其他导入记录或历史版本引用，最后一个引用消失后才清理存储。

## 导入流程与规模

流程为读取 / 类型识别、索引查重、分批保存、完成。普通导入每 32 个文件提交一次；取消会停止后续解析并保留已经处理的批次。同名不同内容进入决策暂存处，完全相同的卡片内容跳过。

解析、指纹与 PNG 缩略图生成由内联 Web Worker 执行，支持项目的单 HTML 构建和 GitHub Pages。ZIP 仅读取中央目录，再逐个成员解压，不同时展开整个压缩包。没有 Worker 的环境会顺序执行并主动让出事件循环。

卡片正文、原图及专属资源正文独立保存在 IndexedDB。页面常驻摘要，详情及导出按需读取完整内容。集合使用记录级存储和小型 ID 索引，保存时只写变化的记录；先写完记录再发布集合索引，读取不完整时显示错误，不自动替换成空库。旧的整数组存储首次启动时迁移。

角色卡每页最多 90 张，正则、脚本、世界书和暂存列表每页最多 50 项；QR 每页 60 个集合。新增 PNG 的列表缩略图最大 240 × 360，原始卡面完整保留。旧图的展示解码最多同时处理两张。

单文件及 ZIP 单个成员限制为 128 MB。普通 ZIP 支持 stored / deflate；ZIP64、分卷和加密包需先解压后通过文件夹导入。可容纳的实际文件总量取决于设备空间和浏览器 IndexedDB 配额，数量不设为 10,000 的硬上限。

网络酒馆拉取逐张把原文件交给同一个导入流程，不累计所有原图。名称引用不含世界书正文时保留为待处理，不构造空世界书。既有插件、聊天记录、非 PNG 图片等专用格式仍保留原入口；文件夹中的非统一格式由原同步处理器处理。

## 验证

```sh
npm run lint
npm run build
node --import tsx --test src/utils/presetResources.test.ts src/utils/baiduApi.test.ts
npm run test:imports
# 可选：加入真实导入样本目录
TAVERN_FIXTURES=/path/to/samples npm run test:imports
```

导入测试使用会执行 structuredClone 的存储适配器，覆盖来源分类、集合分组、原始字段保留、ZIP 成员读取、查重、暂存、单文件替换、失败隔离、取消保留、索引发布中断、编辑后的保存与正文回收、备份完整性、QR 导出、关联索引，以及 10,000 条合成卡片的导入 / 重载 / 按需读取。

真实样本已验证 13 个 JSON 和夜航 ZIP 内原始 PNG。此处的大库测试不代表手机浏览器导入 10,000 张真实 PNG 的内存实测；部署后还需在目标手机、平板、电脑验证实际卡面尺寸、存储配额和 Worker 兼容性。
